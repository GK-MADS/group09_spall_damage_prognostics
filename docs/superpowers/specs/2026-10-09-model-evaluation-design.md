# Model Evaluation and Failure Analysis — Design

Date: 2026-10-09
Status: draft for review
Scope: SIADS 696 failure-analysis assignment for the group09 spall-damage models

## 1. Goal

Produce a rigorous evaluation and failure analysis of our supervised and unsupervised spall-damage models that
scores on every rubric item (6 points):

| Rubric item | Points | Where this design covers it |
|---|---|---|
| Selection of examples | 2 | §6.5 (selection rule), §8 (report §4) |
| Analysis of reasons | 2 | §6.4 (interpretability), §6.1–6.3 (diagnostics) |
| Identification of categories | 1 | §8 (categories table) |
| Proposed improvements | 1 | §8 (improvements table) |

The assignment's Step 1 (ablation, sensitivity, learning curves, failure analysis) and Step 2 (comparison) are
both delivered. Implementing the proposed improvements is out of scope.

### Deliverables

1. A section of the group PDF report (graded), built from figures and tables generated by code in the repo.
2. A Jupyter notebook `models/eval/spall_eval.ipynb` that presents the same figures and numbers.
3. Scripts in `models/eval/` that regenerate every figure, table, and quoted number with one command.

### Success criteria

- Every number in the PDF comes from `models/eval/out/` (no hand-copied values).
- At least 3 failure examples, covering both supervised and unsupervised models and at least 3 failure categories.
- Every approach is evaluated by the same harness with the same folds, metrics, and seed.
- Statistical limits (4 gears, 2 labelled gears) are stated wherever a result depends on them.
- `python models/eval/run_all.py` reproduces `out/` from the parquet tables.

## 2. Context

- Data: PHM 2026 challenge. Training gears Exp-A, B, C, F (32 run ends); validation Exp-G and test Exp-D, E are
  unlabelled and are not used for evaluation.
- Existing models: `models/spall_hi.py` (unsupervised health indices: maha, spe, zpos, zmax, tooth, tooth_maha;
  plus debris and an elapsed-hours proxy) and `models/spall_supervised.py` (non-negative ridge on Exp-A/B tooth
  labels; label-tuned unsupervised HI chosen from a 96-setting grid).
- Existing metric: `challenge_score` — MSE after the best isotonic map of prediction onto truth, pooled and per gear,
  plus Spearman.

Two issues found while designing that the evaluation must handle:

1. **Selection bias.** The label-tuned FM4 HI was selected on the same labels its reported scores use, so those
   scores are in-sample.
2. **Flat ridge alpha.** Ridge alpha 0.1 and 10 give identical scores to four decimals in every existing table.

## 3. Architecture

```
models/eval/
  __init__.py
  harness.py       folds, metrics, gear-level resampling, sign-flip test, detection metric, timing
  adapters.py      one adapter per approach: fit(train_gears) -> self; score(gears) -> run-end table
  ablation.py      Step 1.1
  sensitivity.py   Step 1.2
  curves.py        Step 1.3
  failures.py      Step 1.4: residual ranking, SHAP/LIME/exact decompositions, failure-example figures
  compare.py       Step 2: master table, per-gear dot plot, trajectories, lead time
  cells.py         notebook cell sources
  build_notebook.py  writes spall_eval.ipynb from cells.py (same pattern as eda/scripts/)
  run_all.py       runs every analysis script in order, writes out/
  out/             CSV + PNG + report_numbers.json
  spall_eval.ipynb
tests/test_eval_harness.py
```

The harness reuses `challenge_score`, `run_end_scores`, `HealthyModel`, `condition_correct`, `photo_damage`
(from `spall_hi.py`) and `RidgeDamage`, `load_labels`, `minute_targets`, `GRID` (from `spall_supervised.py`).
It does not reimplement them. The existing scripts are not modified except where a parameter must be exposed for
ablation (for example a flag to skip condition correction); any such change keeps current defaults and outputs.

### Adapter interface

```python
class Approach(Protocol):
    name: str
    kind: Literal["unsupervised", "supervised", "semi-supervised", "baseline"]
    n_tuned: int                    # number of settings selected using labels (0 if none)
    def fit(self, z: pd.DataFrame, ends: pd.DataFrame, lab: pd.DataFrame | None) -> "Approach": ...
    def score(self, z: pd.DataFrame, ends: pd.DataFrame) -> pd.DataFrame:  # experiment, run_num, end_h, score
        ...
```

`z` passed to `fit` contains only the fold's training gears; the harness enforces this (§7).

## 4. Approaches compared

| # | Approach | Kind | Fit on | n_tuned |
|---|---|---|---|---|
| 1 | Health-index candidates (maha, spe, zpos, zmax, tooth, tooth_maha) | unsupervised | pooled healthy baseline minutes of training-fold gears | 0 |
| 2 | Isolation Forest (new) | unsupervised | same baseline minutes, same `FEATS` | 0 |
| 3a | Non-negative ridge, tooth CIs | supervised | Exp-A/B labels in fold | alpha only |
| 3b | Non-negative ridge, all CIs | supervised | Exp-A/B labels in fold | alpha only |
| 4n | Label-tuned FM4 HI, non-nested (as submitted) | semi-supervised | grid chosen on all labels | 96 |
| 4 | Label-tuned HI, nested | semi-supervised | grid re-selected inside each fold | 96 |
| 5 | Elapsed hours | baseline | none | 0 |
| 6 | Debris rate | baseline | none | 0 |

Isolation Forest: `sklearn.ensemble.IsolationForest(random_state=SEED)`; minute score = `-score_samples(X)` on
condition-corrected `FEATS`; run-end value via `run_end_scores` with the same tail and monotone step as the HI.
Defaults: `n_estimators=200`, `max_samples="auto"`, `max_features=1.0`.

Rows 4n and 4 are both reported; their gap measures selection bias.

## 5. Evaluation protocol

### Targets

- **T1 — photo damage.** `photo_damage` on all 32 training run ends (initiation = 1, spall = 2, summed over teeth).
  8 run ends are non-zero (A4, A5, B6, B7, C12, F6, F7, F8); 6 contain a spall (A5, B7, C12, F6, F7, F8).
  Every approach is scored on T1.
- **T2 — tooth labels.** `mean_ex` from `data/labels/spall_scores.csv` on Exp-A and Exp-B (11 labelled run ends).

### Folds

- One set of folds for both targets: leave-one-gear-out over the 4 training gears. Supervised approaches train on
  the labelled gears present in the fold (A and/or B) and are scored on the held-out gear.
- T1 is scored on all 4 held-out gears; T2 only on the folds holding out Exp-A or Exp-B (the A↔B comparison).
- Unsupervised healthy models are always refit without the held-out gear.

### Metrics

- `challenge_score`: `mse_pooled`, `mse_per_gear`, `spearman`.
- **Gear error** (used for every per-gear comparison): fit one isotonic map on all held-out run ends of an approach
  (the pooled map), then average the squared residuals within each gear. `mse_per_gear` is reported but not used to
  compare approaches: photo truth is non-decreasing within a gear and every approach's run-end output is made
  non-decreasing, so a per-gear map fits almost perfectly for any approach (elapsed hours scores exactly 0).
- Detection: a run end is flagged when its score exceeds a threshold set on training-fold gears only. For
  approaches with minute-level scores (HI, Isolation Forest, ridge) the threshold is the 95th percentile of the
  minute scores inside the healthy-baseline window. For run-level baselines (elapsed hours, debris) it is the
  maximum run-1 value. Reported as caught / missed / false alarms out of the 6 spall run ends, plus F1.
- Lead time: hours between the first flagged run end and the first run end whose photo shows a spall, per gear
  (negative = late).
- Cost: wall-clock fit time and score time per fold.

### Uncertainty

The independent unit is the gear. The design reports uncertainty as follows:

1. **Per-gear results are the primary evidence**: every approach's score on each held-out gear, shown as a dot plot.
   Claims take the form "beats the baseline on k of 4 gears, by these margins".
2. **Gear-level bootstrap** (resample gears with replacement, 2,000 draws, `SEED`) reported as a descriptive range,
   not an inferential interval. No run-end bootstrap.
3. **Exact paired sign-flip test** over gears against elapsed hours. The floor (p ≥ 1/16 = 0.0625 for 4 gears,
   p ≥ 0.25 for 2 gears) is printed next to every p-value.
4. **Label-noise check**: T1 rescored using only inspections that were checked by eye (the final two per gear, per
   `eda/README.md`), all other run ends dropped. Report whether the ranking of approaches changes.
5. The in-sample isotonic map in `challenge_score` makes absolute MSE optimistic for every approach; rankings are
   comparable, absolute values are not challenge-score predictions. This is stated in the report.

`SEED = 696` everywhere.

## 6. Step 1 analyses

### 6.1 Ablation (`ablation.py`)

Remove or alter one component at a time; report Δ T1 `mse_pooled` and Δ T2 `mean_ex` (`mse_pooled`) relative to the
full approach.

| Applies to | Ablations |
|---|---|
| HI, Isolation Forest | tooth CIs only vs all `FEATS`; drop each of FM4, M6A, M8A, NA4; add debris bins as features |
| HI, Isolation Forest | condition correction off; pooled standardisation instead of per-gear baseline; steady-state filter off; monotone step none / iso / cummax |
| Ridge | sign split off; log1p compression off; `positive=False` |

Output: `out/ablation.csv`, `out/fig_ablation_heatmap.png` (approach × ablation, colour = Δ score).

### 6.2 Hyperparameter sensitivity (`sensitivity.py`)

One-at-a-time sweeps around the chosen value, one line per held-out gear.

| Approach | Parameter | Values |
|---|---|---|
| HI | `base_h` | 1.5, 3, 4.5, 6 (bounded by run-1 length) |
| HI | `tail` minutes | 10, 30, 60, 120, 240 |
| HI | `BREAK_IN_H` | 0, 0.25, 0.5, 1 |
| Ridge | alpha | 13 values, log-spaced 1e-3 to 1e4 |
| Isolation Forest | `n_estimators` | 50, 100, 200, 500 |
| Isolation Forest | `max_samples` | 64, 256, 1024, "auto" |
| Isolation Forest | `max_features` | 0.25, 0.5, 1.0 |
| Isolation Forest | seed | 5 seeds at defaults (variance only) |
| Label-tuned (nested) | selected setting per fold | frequency each setting wins across folds |

The ridge sweep must explain the flat alpha 0.1 = 10 result (record coefficient norms per alpha).

Output: `out/sensitivity_*.csv`, `out/fig_sensitivity.png` (small multiples).

### 6.3 Learning curves (`curves.py`)

- Unsupervised: fit the healthy model on 1, 2, or 3 of the non-held-out gears (all combinations); separately vary
  healthy-baseline hours (1, 2, 3, 4.5, 6).
- Ridge: train on the first k inspections of one labelled gear (k = 1 … all), test on the other gear.
- Output: `out/curves_*.csv`, `out/fig_learning_curves.png`. Interpretation states plateau vs still improving.

### 6.4 Interpretability (`failures.py`)

| Approach | Method | Note |
|---|---|---|
| Ridge | `shap.LinearExplainer` | exact for a linear model |
| Isolation Forest | `shap.TreeExplainer` | supports `IsolationForest` |
| HI tooth / tooth_maha / maha | exact per-CI decomposition of the closed-form score | tooth: per-CI clipped z / n; maha: per-CI share of whitened distance |
| All | `lime.lime_tabular.LimeTabularExplainer` on the run-end prediction | cross-check against the exact methods; report agreement (rank correlation of attributions) |

Each explanation is paired with a minute-level time plot of the score over the gear's life with run boundaries,
rig restarts, temperature, and torque marked.

### 6.5 Failure-example selection

Rule, applied before writing any example:

1. For each approach, compute per-run-end residuals on T1 (after the pooled isotonic map) and on T2.
2. Rank run ends by absolute residual within each approach.
3. Pick from the top of these lists so the final set (a) has at least 3 examples, (b) includes at least one
   supervised and one unsupervised approach, and (c) spans at least 3 categories from {systematic, random,
   edge case, operational}.
4. Record the full ranked lists in `out/failure_candidates.csv` so the selection is auditable.

Hypotheses to confirm or reject with the data (not pre-committed examples):

| Hypothesis | Expected category |
|---|---|
| All-CI scores jump at rig restarts (Exp-A run 3, photo = 0) | systematic |
| Exp-A run 2 is a byte copy of run 1 | operational / data quality |
| Exp-C: longest life, damage only at run 12, two camera setups | edge case + label noise |
| All-CI ridge learns Exp-B restart shifts as wear | systematic + overfitting |
| Exp-B gradual wear vs Exp-A late spalls | edge case (regime difference) |

Each selected example is written up with the assignment's a–d structure.

## 7. Step 2 comparison (`compare.py`)

- Master table `out/comparison.csv`: one row per approach (§4); columns: T1 `mse_pooled`, `mse_per_gear`,
  `spearman`; T2 `mean_ex`; caught / missed / false alarms, F1; lead time; gears beating elapsed hours (k/4) and
  sign-flip p with floor; label-noise-check rank; fit and score time; `n_tuned`.
- Figures: `fig_per_gear_dots.png` (primary), `fig_trajectories.png` (top 3 approaches vs photo truth per gear),
  `fig_lead_time.png`.
- Winner rule, fixed in advance: (1) most gears beating elapsed hours on T1 gear error; (2) lowest T1
  `mse_pooled`; (3) fewest `n_tuned`.
- Interpretation ties results to model assumptions: Mahalanobis assumes roughly Gaussian CIs (impulsive CIs are
  heavy-tailed); Isolation Forest uses axis-aligned splits; ridge assumes a linear, non-negative map; rig restarts
  violate the stationary-healthy-state assumption shared by every approach.

## 8. Write-up

### PDF section outline (6–8 pages, 6–8 figures, plus appendix)

1. Evaluation method: protocol, targets, and their limits (gear counts, p floor, in-sample isotonic map).
2. Step 1.1–1.3 results: one figure and one paragraph each.
3. Comparison: master table, per-gear dot plot, winner rule and result.
4. Failure examples 1–3+ (a–d each).
5. Categories table: example × category × evidence.
6. Improvements table: cause → fix → expected impact, each linked to a failure.
7. Ethics and impact: missed spall → gearbox failure; false alarm → unnecessary teardown; asymmetric costs and the
   alarm threshold.
8. Reproducibility appendix: command, package versions, `SEED`, all parameters.

### Single source of numbers

- Every figure is written as PNG at 300 dpi; every table as CSV.
- `out/report_numbers.json` holds every number quoted in the prose, keyed by name.

### Notebook

- `spall_eval.ipynb` is generated by `build_notebook.py` from `cells.py`, one section per PDF section.
- It reads `out/` only and runs in seconds; an optional cell calls `run_all.py` to regenerate.

## 9. Error handling

- Missing parquet tables: raise with the recreate command from the README.
- Missing `shap` or `lime`: `failures.py` raises with the install command; other scripts still run.
- An adapter that sees a held-out gear in `fit` raises (see tests).

## 10. Testing

Fast tests in `tests/test_eval_harness.py`, synthetic data, same style as `tests/test_spall_hi.py`:

- Fold isolation: the held-out gear never appears in data passed to any adapter's `fit`.
- Sign-flip test returns p = 1/16 when one approach wins on all 4 gears, and 1/4 on 2 gears.
- Detection counts and lead time on a hand-built example.
- Every adapter returns the required columns for every run end.
- Isolation Forest adapter is deterministic for a fixed seed.

Slow test (marked `slow`): `run_all.py` on the real parquet tables completes and writes every expected file.
